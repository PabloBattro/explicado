A small personal assistant setup

Three agents and the program that moves the money

One assistant does not need to do everything. Email, groceries, code, and payments are handled separately because each job needs different access — and different limits.

Four chats, four tools

They look similar in Telegram. Behind the bots, three agents can understand requests and make choices. The payment program simply follows a fixed set of steps.

Wall: the system blocks it Agreement: a rule everyone follows

Not every limit works the same way. Some are blocked by the system. Others are rules the setup is expected to follow.

01 · agent

Alfredo

A personal assistant that is always around.

Its job

Help with everyday tasks and put together a daily summary.

How to reach it

Through a private Telegram bot.

What it can do

Read the user's email without changing it, send mail from its own address, create events on its own calendar and send invites, check payment details, and suggest a payment to Gringotts.

Walls

Google rejects attempts to write on the user's calendar. Gringotts gives Alfredo no way to confirm or run a payment.

Agreements

Email content is treated as information, not as instructions. Alfredo does not use the other agents' tools, even though they share a computer.

02 · agent

Changuito

The shared grocery list for the household.

Its job

Keep the household grocery list up to date.

How to reach it

Through its bot in a family Telegram group.

What it can do

Add, remove, and sort items based on the family's messages.

Walls

None are claimed here unless another system actually enforces them.

Agreements

Changuito does not read email, work on code, look for payment access, or talk to the other agents. Because they share a computer, these are rules, not guarantees.

03 · agent

César

The agent that works on code projects.

Its job

Turn chat requests into changes that can be reviewed in a code project.

How to reach it

Through a private Telegram bot.

What it can do

Work on approved GitHub projects with its own account, suggest changes, and show results that can be checked without reading code.

Walls

If César tries to open a project it was not invited to, GitHub returns an error. This has been tested.

Agreements

César does not use email, grocery, or payment tools, even though it shares a computer with the other agents.

Having an account does not mean being able to use it. César has an email address to register its GitHub account, but no tools to read or send email.

Review without reading code

The result is checked by what it does and whether the automated checks pass — not by reading every changed line.

04 · program

Gringotts

It looks like another agent in Telegram, but it does not think. The same request always gets the same result.

Its job

Show payment information, prepare confirmations, and run payments that a person approved.

How to reach it

Directly through its Telegram bot. Alfredo uses a separate, much more limited entrance.

What it can do

Show the status of a payment, check a suggestion, create a pending confirmation, and run it only after a person confirms directly.

Walls

Alfredo's entrance only supports reading and suggesting. It has no option to confirm, run, cancel, or even view the pending confirmation.

Agreements

No important money control depends on an agreement. The checks still work even if an agent does not follow instructions.

A suggestion is not a payment

Alfredo can get things started. Money only moves after a person confirms directly in the Gringotts chat.

If a confirmation is already open, a new suggestion is rejected. It does not replace the first one or wait in line. The reply sent back to Alfredo also leaves out anything that could help approve it. The only tool that touches real money is the one that cannot improvise.

Where the real walls are

Separate names and chats keep things tidy. A real boundary exists only when another system rejects the action or never offers it in the first place.

Three roommates, one house

Alfredo, Changuito, and César share a computer and the same login. The limits between them are rules set in the system's settings.

A written rule does not remove access

Telling an agent “do not do this” can guide its behavior, but it does not remove a tool that is still available.

The network is the real wall

Gringotts runs somewhere else. The shared Mac only gets the two small entrances it offers: read and suggest.

A person opens the last door

Alfredo suggests. A person confirms. There is no second way to run the payment.

The goal is not to make every tool capable of everything. Each one gets a clear job, visible limits, and real walls where a mistake would matter most.
